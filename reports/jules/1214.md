## Verdict
partly done. The internal/usage/codex.go parser handles multiple rollouts correctly by tracking usage per `sessionID`, but internal/usage/project.go naively parses every file and sums them, causing the 3x overcount, while internal/subagent/codex.go undercounts because it sums incremental `turn.completed` events that may not be present.

## Evidence
- `internal/usage/codex.go:137` `bySession[sessionID] = latest` tracks tokens using a session ID derived from `session_meta`, ensuring multiple rollout files from resumes only contribute their final latest usage.
- `internal/usage/project.go:317` `filepath.Walk` naively loops all files and `internal/usage/project.go:322` `matched, breakdown, modelTokens := parseCodexRollout(path, targetRepo)` parses each as a distinct block. Then `internal/usage/project.go:325` `attr.Tokens.InputTokens += breakdown.InputTokens` directly adds it. Since a resumed session creates a new rollout file containing all prior tokens, this sums the cumulative total from each resume file instead of taking the maximum or keyed latest.
- `internal/subagent/codex.go:491` `p.r.TokensTurn = p.r.InputTokens + p.r.OutputTokens` adds `InputTokens` recursively from `turn.completed` events (`internal/subagent/codex.go:465`).
- The fixture `internal/subagent/testdata/codex-987-rollout.jsonl` contains `token_count` events but no `turn.completed` events, resulting in 0 tokens tracked by `internal/subagent/codex.go:491`, exactly matching the 0 token symptom in the loom runs.
- `internal/subagent/codex.go:476` `if e.Payload.Type == "token_count" && e.Payload.Info.LastTokenUsage.Input > 0 {` parses the correct last input tokens into `p.r.ContextTokens`, but it is completely ignored when computing `TokensTurn` and `TokensCumulative`.
