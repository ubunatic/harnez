# 579 — Fix inconsistencies in lite quota-1 init guidance

**Status**: Open
**Priority**: P2
**Severity**: Moderate
**Category**: Documentation
**Related**: `harnez init --variant lite --quota-1`

---

## 1. Problem & Motivation

Reviewing files generated by `harnez init --variant lite --quota-1` in the `lmcoder` checkout surfaced three misleading or internally inconsistent guidance changes:

- Generated `AGENTS.md` points to “Invariant 10” for the media verification gate, while generated `AgenticLoop.md` numbers that gate Invariant 7 and ends at Invariant 9.
- Generated `Spec.md` describes `spec/telemetry.yaml` as an example, but that file does not exist in the target checkout.
- Generated `IssueTracking.md` says every ticket must define `/goal`, although this existing repository has many tickets without one and the rule gives no migration or new-ticket-only scope.

An independent Terra review confirmed these findings.

## 2. Goal

`/goal`: The lite quota-1 files generated by `harnez init` contain valid cross-references and examples, and tracker requirements make clear whether they apply to new tickets or require existing-ticket migration. Verify the corrected behavior against a representative initialized project.

## 3. Implementation & Verification Plan

Trace each generated statement to its managed source/template, correct the sources, and verify `harnez init --variant lite --quota-1` produces consistent references and applicable tracker guidance. Confirm examples refer to files that exist in the target project or are clearly labeled optional.
