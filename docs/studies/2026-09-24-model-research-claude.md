Question: Are the Claude and agy Claude entries in the model table accurate for identity, route, effort, Go/TUI/SQL skills, roles, and use?
Method: Web-only research on 2026-09-24; checked Anthropic model/API and Claude Code documentation, plus Antigravity/agy model documentation. Skills and subjective workflow claims require model- and route-specific comparative evidence.
Findings:
- Anthropic currently documents Haiku 4.5, Sonnet 4.6, Opus 4.6 and newer; API IDs are versioned. Claude Code aliases haiku/sonnet/opus are moving aliases, not fixed versions. https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions (accessed 2026-09-24)
- Antigravity documents Sonnet 4.6 (thinking) and Opus 4.6 (thinking), with selection through its own UI/CLI. This is Google's Antigravity route and must not be equated with Anthropic direct API. https://www.agy.dev/docs/models/ (accessed 2026-09-24); https://www.agy.dev/docs/cli/headless/ (accessed 2026-09-24)
- Direct Claude effort: Opus 4.6 supports low/medium/high/max; effort changes thinking allocation. Current Anthropic docs give no evidence that Haiku supports effort; Sonnet 4.6 does have effort controls. https://platform.claude.com/docs/en/build-with-claude/effort (accessed 2026-09-24)
- Antigravity UI presents thinking variants, but its public model page does not establish low/medium controls for Claude models. Agy CLI docs should be consulted for exact flags; no inference from Anthropic support is valid.
- Anthropic recommends Haiku for quick/simple tasks, Sonnet for general coding, Opus for harder work. This is broad guidance, not validation of the table's precise narrow-edit, reviewer, advisor, orchestrator, quota, or tool-use claims. https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code (accessed 2026-09-24)
- No qualifying route-specific controlled evidence located for Go, TUI, or SQL relative skill ratings; likewise no measured first-token latency evidence for agy Sonnet. Treat these as unknown pending reproducible evaluations.
Inconclusive: Cost units, quota-out behavior, operational roles, and subjective quality labels appear to describe local routing/account conditions not established in vendor docs. Agy-specific API/backend routing internals are not independently verified.
