# Retro: lean sprint 496, 488, 497 (2026-09-22)

The host was an Opus orchestrator and the developer was codex luna:low through `harnez agent`.
The orchestrator did no coding. Everything went through tickets, with review of the diffs.

## Went well

- **Preflight paid off before the sprint.** The model eval found that 289 was already fixed,
  so no developer was spent on it. All three sprint tickets passed their preflight.
- **luna:low is enough for mechanical and small bug tickets.** 496 (gofmt plus a
  `make check` gate) and 488 (`.git` needs `HEAD`, hermetic tests) landed right on the first
  try, in 1–2 minutes each.
- **Pre-work written into the ticket worked.** The 488 worktree case, the 497 tier mapping and
  the M2/M3 refinements all went into the ticket, and the developer executed them without
  further prompting.
- **Cost measured.** The whole sprint used 2% of the Codex 5-hour window and less than 1% of
  the weekly allowance. See `docs/ModelAdvisoryEval.md`.

## Went wrong

- **A bug hid behind a changed assertion.** 497 M1 hard-coded `model_reasoning_effort=medium`
  on resume, and updated `TestCodexResumeUsesSameSandboxAsRun` to expect it. Green tests,
  wrong behaviour. `make install` had already shipped it. Only the host's diff review caught
  it.
- **M2 fixed the bug but not the structure.** It used runtime interface checks and an
  optional tier argument, and copied the validation. It took a third milestone (M3) to put
  `Model` on the interface. A stronger model would probably have done M1 in one go, so a
  ticket that changes an interface is a candidate for luna:med.
- **Quota-1 left M3 unverified.** The developer's only test run failed, it fixed a helper, and
  it correctly did not run the tests again. The host's verification run passed.
- **Resuming across a buggy install.** Resuming `dev-lean` would have run at medium effort
  because of the M1 bug, so M2 started a fresh session instead.

## Insights

- In a cheap developer's report, "updated a stale assertion" means review that assertion first.
- Changing an interface signature is worth one step up in model tier. A local fix is not.
- A live canary has to be able to tell the fix from the default. `luna:low` resumed at low
  either way, because `config.toml` says low. Only `luna:med` proved the flag is passed.
