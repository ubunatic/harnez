`apply`/`diff`/`status` commands, over six milestones. It was the first sprint with the role table
from `docs/ModelAdvisoryEval.md`: terra:low and sonnet as advisors, luna:med as developer
(switched to sonnet at M5), sonnet as reviewer, and an Opus host that wrote no code.

## What went well

- The advisors agreed on the milestones and traps, so the pre-work was written from their answers
  with little host effort.
- Read-only plan turns found gaps in the host's pre-work twice.
- The ticket carried everything across a vendor switch and across fresh sessions.
- Verifying the golden hash on pre-change code turned "trust me" into a proven invariant.

## What went wrong

- **Removal dead from the CLI (M5).** Every test called `ApplyAllVariant` directly, while `cmd`
  passed a pre-filtered config. Found by the host tracing the CLI path, not by a test.
- **A pre-work wording caused scope creep (M3).** "mcpServers must survive" led to a
  merge-by-name change. The design says `mcpServers` is always applied.
- **Claude resumes are broken inside Claude Code (498).** Plan-then-resume failed for the sonnet
  developer, so every Claude milestone ran in a fresh session.
- **Codex weekly quota ran out.** It went 97% → 99% by M4 and forced the vendor switch.

## Lessons

- Every feature ticket needs one acceptance test through the real entry point (CLI).
- Pre-work must name concrete cases, checked against the design, not categories ("user keys").
- Check the weekly quota before every milestone; the switch threshold worked as intended.
- Name milestones in reports, not just "M3". This rule is now in `AgenticLoop.md` §4.
