Motivation

Why harnez?

Problem

Configuration Drift & Blind Spots

AI coding agent setups drift across machines and providers. Tool permissions wipe on updates, prompt conventions diverge across repositories, multi-agent skills need disparate target directories, and unexpected rate limits or silent tool failures stall workflows without telemetry.

Approach

Declarative Source of Truth & Native Hooks

A single declarative config.yaml idempotently manages global configs, local project scaffolding, and cross-agent skills. Two-stage PreToolUse hooks rewrite commands to proxy stdio unbuffered and capture execution metrics directly into a local SQLite database.

Result

Deterministic, Observable Engineering

Zero drift across all agent harnesses, one-command project onboarding via harnez init, live cross-provider quota tracking with rate-limit protection, and quantitative tool call reliability metrics via harnez stats.

Real-Time Observability

Unified Token, Quota & Hardware Dashboard

harnez usage (aliases: quota, tokens) unifies live rate-limit quota windows, token velocity sparklines, host hardware load, remote SSH nodes, and microphone speech meters into one interactive btop-style dashboard.

Multi-Provider Quotas

Live 5-hour and weekly rate limits for Claude Code, Gemini/Antigravity, and OpenAI Codex with reset countdowns and shared file-locked disk caching.

Hardware & Remote Streaming

Local CPU, RAM, and GPU/VRAM telemetry (AMD Cezanne/Phoenix, NVIDIA) alongside remote node metrics streamed over SSH (--host @x600).

Two-Stage Hook Interception

PreToolUse hooks rewrite commands into harnez exec -- <cmd>. The hook process exits immediately; the wrapper proxies unbuffered stdio, captures timing and exit codes, and writes SQLite telemetry in a bounded goroutine without blocking the agent.

Noise Distillation Engine

harnez distill automatically strips passing test noise, repetitive logs, and ANSI escape codes before output enters the agent's context window, saving over 50% in context tokens and bandwidth.

Native Multi-Agent Hooks

Includes dedicated hook adapters: harnez agy-hooks for Google Antigravity's dynamic top-level hooks.json schema, Claude Code settings.json hooks, and Codex shell wrappers.

Architecture

How it works

1

Two-Stage Hook Interception

PreToolUse lifecycle hooks rewrite tool invocations (such as Bash or run_command) into harnez exec wrappers. The hook returns instantaneously, letting harnez exec supervise execution, proxy unbuffered stdio, and write telemetry asynchronously to SQLite.

2

Key Merge, Not Replace

harnez only mutates keys it explicitly manages (effortLevel, permissions, hooks, env, spinnerVerbs, mcpServers). User preferences, dark themes, and auth tokens in settings.json and hooks.json are strictly preserved.

3

Managed Markdown Boundaries

Content in AGENTS.md and CLAUDE.md is bounded by HTML comments (<!-- harnez:begin ... -->). Custom rules, project architectures, and unmanaged sections outside those comments are never overwritten.

4

Shared Caching & Lock Coordination

Live quota queries and hardware metrics are cached on disk with file locks (~/.claude/harnez-quota-cache.json). Multiple running terminals and agent subprocesses share cached readings without hitting upstream API rate limits.
