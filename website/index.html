harness

One config.yaml drives everything Claude Code and AI agents read — permissions, model settings, hooks, instructions, cross-agent skills, and engineering conventions. Apply is idempotent.

settings.json CLAUDE.md AGENTS.md commands/ skills/ docs/ hooks
Quick install
$ git clone https://codeberg.org/ubunatic/harnez
$ cd harnez
$ make install # builds and installs to ~/go/bin

What it manages

Model & effort

Set model and effort once; every apply keeps settings.json in sync.

Permissions

Allow/deny lists are merged, not replaced — your user-managed keys survive every apply.

Lifecycle hooks

Declare Stop, PreToolUse, and other hooks in YAML; harnez writes the right JSON shape.

CLAUDE.md / AGENTS.md

Managed sections live inside HTML-comment markers. Unmanaged project rules are never overwritten.

Multi-agent skills

Distributes slash commands & skills across Claude (~/.claude/commands/), Gemini (~/.gemini/skills/), and Codex.

Language & practice docs

Bundles conventions for Go, Bash, Make, Rust, Zig, C++, GTK4, Git, Markdown, Canary-first probes, and Spec-driven architecture.

MCP servers

Declare MCP server definitions in mcp_servers:; harnez writes them into settings.json.

Project setup & upgrade

init sets up AGENTS.md, symlinks CLAUDE.md, copies local docs, and reconciles Makefile targets.

Quick start

# sync global ~/.claude config and shared skills (idempotent)
$ harnez apply --force-docs

# preview changes without writing
$ harnez diff

# check configuration and installed doc status
$ harnez status

# set up or upgrade a project directory with language docs
$ harnez init -d /path/to/project -y

# upgrade all sibling repositories in workspace
$ make init-siblings

Commands reference

Command Key flags What it does
apply -c -t -d --force-docs Sync global ~/.claude: settings, hooks, commands, docs
init -c -d --docs --summary Set up a project: AGENTS.md, doc copies, Makefile targets
diff -c -t Preview changes without writing (uses diff -u)
clean -c -t Remove managed keys from settings.json; strip MD sections
status -c -t Print config summary and check which items are present on disk

All commands accept -c <path> (config file) and -t <dir> (Claude config directory). The binary is self-contained — no flags needed for the common case.

How it works

1

Key merge, not replace

harnez only writes the keys it owns (model, effortLevel, permissions, hooks, …). Every other key in settings.json — theme, plugins, auth — is preserved.

2

Managed sections in Markdown

Content in CLAUDE.md / AGENTS.md is wrapped in HTML-comment markers. Sections outside those markers are never modified. Multiple sections coexist independently.

3

Symlink convention

AGENTS.md is the canonical file (readable by any agent); CLAUDE.md is a symlink so Claude Code finds it. Same pattern globally: ~/.claude/CLAUDE.md is real; ~/AGENTS.md links to it.

4

Idempotent by design

Run harnez apply as often as you like. If settings drift, re-running restores the managed keys while leaving everything else alone.

target_dir: ~/.claude

  - golang
  - bash
  - make

permissions:

    - "Bash(make *)"
    - "Read(~/projects/**)"

  - event: Stop
    command: "ffplay -nodisp -autoexit /usr/share/sounds/…"

commands:
  - name: review
    description: "Review current branch against main"
